          How the proof works
          
  
          Does prompt20.com see my prompt or my key?
          No. Your browser encrypts each message to the model's key, the key named inside the enclave's hardware quote, and sends it to cloud-api.near.ai. NEAR AI's gateway relays only ciphertext, and replies come back encrypted to a one-time key made in this page. The page's Content-Security-Policy only allows connections to NEAR AI, prompt20's own pages and data API, and NVIDIA's public key list. It loads no analytics. Only the public attestation evidence goes through prompt20.com, to reach Intel's and NVIDIA's verifiers.
          
  
          What does the proof show?
          That the model ran in a non-debug Intel TDX enclave with NVIDIA confidential GPUs, that the hardware quote contains this run's fresh random nonce and the model's signing key, that the measured enclave app is the one NEAR AI serves the model from today, that every message was encrypted to that key, and that every reply was signed by it over the exact encrypted request and response bytes. The prompt is sent only after the hardware checks pass.
          
  
          What does it not show?
          It does not prove the optimised prompt behaves the same in every case, only on your test cases, and your must and must-not rules are not signed. Token counts use the Qwen tokenizer, so other models count a few percent differently.
          
  
          Can I check a receipt without this page?
          Yes. The source and a command-line verifier are public: npm run verify checks the sample receipt, asking Intel, NVIDIA and NEAR AI again.
